# Token 算力链监控

以技能内的确定性脚本作为数字事实来源，再由 Codex 解释信号。不要从新闻摘要或模型记忆中补造价格、指标或资金数据。

## 运行

1. 定位本 `SKILL.md` 所在目录。
2. 运行：

   ```bash
   python3 scripts/price_monitor.py --format json
   ```

3. 若脚本成功，基于 JSON 中的 `data_quality`、`results` 和 `errors` 生成中文报告；需要给用户看原始表格时可改用 `--format markdown`。
4. 若用户要求催化、公告或新闻，必须另外浏览当前来源并逐项引用。数值行情仍以脚本结果为准，来源时间不同要明确区分。

## 报告要求

- 开头写明生成时间、行情时间、交易时段和成功/失败标的数。
- 先报告数据质量，再基于 `sector_summary` 输出板块概览，然后给风险观察结论。
- 板块概览必须覆盖关注池中的全部板块，并显式展示“光模块/光通信”“先进封装”和“存储芯片”；即使数据失败也保留板块并说明缺失，不得静默省略。
- 基于 `decision_matrix` 输出完整的盈亏比决策矩阵，包括优先观察、赔率较优但等待位置确认、等待改善、风险收益偏弱、结构风险和数据不足；空层级也要保留。
- 明细表至少包含：板块、市场、角色、代码/名称、现价、涨跌幅、MA10/MA20、均线参考区、止损参考、目标参考、盈亏比和信号。
- 把 `quote_status != fresh`、`metrics_status != ok` 或 `errors` 显著展示；数据不完整时不得给方向性结论。
- 使用“观察候选、风险收益偏弱、跌破参考、等待确认”等措辞，不输出确定性买卖指令，不假设用户持仓或成本。
- 区分行情事实、机械指标和解释性判断。结尾注明这是研究与风险监控，不构成投资建议。

## 关键边界

- 默认脚本只读，不会修改关注池或历史状态。只有用户明确要求保存时才使用 `--state-output <path>`。
- 工作日不等于交易日；脚本只能识别星期与交易时段，法定休市仍需根据行情时间判断。
- 免费公开接口可能延迟、限流或变更。任一接口失败时保留错误，不使用旧配置伪装成实时结果。
- 风险收益比只衡量脚本定义的几何关系，不代表上涨概率，也不能替代基本面、公告和流动性检查。

计算公式、信号语义和数据源限制见 [references/methodology.md](references/methodology.md)。需要调整关注池时编辑 [references/watchlist.json](references/watchlist.json)，保持代码唯一且市场字段为 `a` 或 `hk`。
